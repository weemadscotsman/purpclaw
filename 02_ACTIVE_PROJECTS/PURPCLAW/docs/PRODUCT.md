# PurpClaw Product Definition

> Version source: `package.json` · Updated: 2026-08-04 · Status: CURRENT

PurpClaw is a local-first AI workstation OS. It provides terminal and graphical operator surfaces, persistent sessions and memory, multi-provider routing, governed tools, MCP, delegation, checkpoints, orchestration and optional messaging, voice, vision and companion lanes.

## Product Boundaries

- PurpClaw is the product and runtime.
- Oracle is the senior coordinating intelligence role.
- Domain chairs, including Hermes for engineering, are governed organisational roles.
- Nous Hermes Agent, Claude Code, Codex and MiniMax Code are external behavioural references, not product identities or separate operating systems inside PurpClaw.
- Registered capability does not imply configured, healthy or proof-backed execution.

## Stable Differentiators

- One governed runtime shared across CLI, TUI, Web and MCP.
- Persistent and resumable sessions with explicit memory boundaries.
- Tool permission evaluation and auditable execution evidence.
- Timeline, Meeting Memory, Soul Memory, Cognitive Spine, Experience, Improvement and Truth boundaries.
- Council voting and domain chairs for governed decisions.
- Donor Archaeology that extracts behavioural laws and provenance rather than copying identity.
- Residue, Presence and Timeline for organisational continuity.

## Current Product Limits

- Wave 1 must prove runtime persistence, permission-path convergence and provider-routing truth.
- Shell mutations are not guaranteed to receive automatic file rollback.
- Delegated write-capable children require registered isolation when operating concurrently.
- Prompt-level tool disclosure needs reduction despite the broad registry.
- Semantic compaction needs stronger decision, constraint and evidence retention tests.
- Optional providers and services require local configuration and live verification.
