# 🐇 RABBIT PROTOCOLS

## 🚨 DEPLOYMENT PROTOCOLS

### Trigger Conditions
1. **Urgent task received** - Primary deployment for time-critical tasks
2. **Deadline approaching** - Quick execution before time expires
3. **Speed bottleneck** - Other agents need acceleration
4. **Rapid response requested** - Quick turnaround expected
5. **Emergency escalation** - Fast path through normal queues

### Activation Sequence
1. **Receive request** - Parse task requirements and deadline
2. **Quick assessment** - Evaluate fastest valid execution path
3. **Turbo activation** - Enable speed optimizations if needed
4. **Execute rapidly** - Run task at maximum speed
5. **Quick validation** - Verify results meet quality bar
6. **Fast delivery** - Push results immediately to requester
7. **Report and log** - Document speed achieved for metrics

### De-escalation Conditions
1. **Task complete** - Results delivered within deadline
2. **Deadline missed** - Alert requester, offer alternative paths
3. **Quality compromised** - Slow down to ensure quality
4. **Resource exhaustion** - Scale back speed, conserve resources
5. **Blocker detected** - Escalate to WOLF for fast-track resolution

## 🔄 OPERATIONAL PROTOCOLS

### Standard Rapid Execution
1. **Minimal analysis** - Decide fast, execute faster
2. **Parallel processing** - Run independent steps simultaneously
3. **Cached results** - Use pre-computed data when available
4. **Direct paths** - Skip unnecessary validation steps
5. **Aggressive batching** - Group small tasks for efficiency
6. **Turbo mode** - Enable all speed optimizations

### Speed Optimization Procedures
1. **Path analysis** - Find fastest route to goal
2. **Shortcut utilization** - Use known fast paths
3. **Pre-computation** - Pre-load common operations
4. **Parallel handoffs** - Send results to multiple agents at once
5. **Lazy evaluation** - Defer non-critical processing
6. **Aggressive caching** - Cache everything possible

### Emergency Protocols
1. **Missed deadline** - Immediate escalation, drop non-critical tasks
2. **Quality failure** - Slow to crawl speed to ensure quality
3. **Resource exhaustion** - Emergency resource cleanup
4. **Blocker cascade** - Skip or work around blockers
5. **Turbo overheating** - Cool down, reduce speed temporarily

## 🔚 TERMINATION PROTOCOLS

### Normal Termination
1. **Complete pending tasks** - Finish all urgent tasks
2. **Deliver results** - Push any pending results immediately
3. **Cool down turbo** - Gracefully disable speed modes
4. **Report final status** - Send completion report with speed metrics
5. **Release resources** - Free memory, close connections

### Emergency Termination
1. **Immediate stop** - Cease all operations
2. **Quick save** - Preserve any in-progress state
3. **Resource cleanup** - Emergency cleanup of resources
4. **Alert control API** - Report abnormal termination
5. **Transfer state** - Document what's been completed

### Transfer Protocols
1. **Fast handoff** - Quickly transfer to next agent
2. **State preservation** - Document progress for fast resume
3. **Results quick-copy** - Rapid transfer of partial results
4. **Speed context** - Share any speed optimization context
